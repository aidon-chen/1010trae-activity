# 1010 Trae 活动

1010 Trae 活动页面集合。主页和快问快答使用静态 HTML；幸运转盘由本机 Node.js + SQLite 服务保存库存和抽奖记录，无需构建工具或第三方运行依赖。

## 页面说明

| 文件 | 说明 |
| --- | --- |
| [index.html](index.html) | 活动主页 |
| [lucky-wheel.html](lucky-wheel.html) | 幸运转盘 |
| [quiz-proto.html](quiz-proto.html) | AI 圈梗与常识快问快答，81 道题，每轮 5 题 |

## 快速开始

运行环境：Node.js **24.15 或更新的 24.x**，加入系统 PATH。项目没有第三方 npm 运行依赖，无需执行 `npm install`，也无需另外安装数据库。

首次使用，在 PowerShell 中克隆并启动：

```powershell
git clone https://github.com/aidon-chen/1010trae-activity.git
cd 1010trae-activity
node --version
node scripts/service.cjs start
```

已有仓库则进入现有 `1010trae-activity` 目录，执行启动命令即可。Edge、Chrome 或其他浏览器可打开以下页面：

| 页面 | 本机地址 |
| --- | --- |
| 活动主页 | <http://127.0.0.1:5173/> |
| 幸运转盘 | <http://127.0.0.1:5173/lucky-wheel.html> |
| AI 快问快答 | <http://127.0.0.1:5173/quiz-proto.html> |

转盘必须通过本地服务使用，直接双击 HTML 文件不能抽奖。`localhost:5173` 与 `127.0.0.1:5173` 访问同一后端库存；旧浏览器缓存按域名隔离，迁移时需使用原地址。

### 日常启动与开发

在仓库目录使用下列命令：

| 场景 | 命令 | 说明 |
| --- | --- | --- |
| 后台启动 | `node scripts/service.cjs start` | 关闭终端或 Codex 后继续运行 |
| 停止后台服务 | `node scripts/service.cjs stop` | 保留奖池和记录 |
| 重启后台服务 | `node scripts/service.cjs restart` | 修改后端代码后使用，保留数据 |
| 前台开发 | `npm start` | 先停止后台服务；Ctrl+C 停止前台服务 |
| 自动化检查 | `npm test` | 使用独立测试数据，不消耗正式奖池 |

Windows 也可运行 `scripts/Start-Local.ps1` / `scripts/Stop-Local.ps1`。前台和后台服务不能同时占用 5173；端口被其他程序占用时，应先处理冲突。启动失败查看 `data/service.log`。

后台服务异常退出后自动重试，连续 8 次快速启动失败后停止重试。Windows 重启后需重新执行启动命令，电脑休眠期间服务暂停。服务仅绑定本机地址，适合工作人员在现场电脑操作，未提供局域网或公网参与入口。

## 现场使用方案

1. **开场检查**：启动服务、打开转盘，确认页面显示“本地服务已连接”，核对剩余库存和已抽次数。首次新库为 200 签、58 份实物，初始中奖率 29%；之后概率按剩余数量变化，不是固定 29%。两个活动时段共用普通奖池，不按时段重置。
2. **迁移旧记录**：如出现旧缓存提示，先导出备份并核对已发礼品，再选择“迁移旧记录并继续”。服务当前奖池尚未开抽时才可导入；原浏览器缓存不删除，旧手办等级不重新分配。不能用新满库存覆盖已经发放的奖品。
3. **核验抽奖机会**：参与者完成快问快答，五题全对后由工作人员核验 1 次抽奖机会，再在转盘点击一次“抽奖”。问答与转盘尚未自动联动，也没有按参与者身份限制次数，资格和重复参与由工作人员管理。
4. **抽奖与发放**：以页面结果及记录编号核对奖品后发放。库存由服务器扣减，同一电脑多个浏览器共用库存；连接中断时使用“重试本次”取回同一请求结果，不重复扣库存。
5. **管理与收场**：点击“管理奖池”→“展开”（或 Ctrl+Shift+A），导出全部抽奖记录 CSV，并下载数据库备份。随后停止服务；下次启动继续原奖池。

默认配置中，二等奖“TRAE 宝手办”共 5 份（原新增手办 1 份已并入）。Agent 用户领取的 10 套贴纸、12:30 定时抽奖的 5 套冰箱贴不进入普通转盘。

### 新活动与自定义奖池

管理区可修改新奖池草稿的名称、等级、数量和颜色，点击“保存为新奖池”后生效；草稿不会改变当前活动库存。“按文档新建奖池”使用默认 200 签配置。

新建会归档旧奖池、保留全部历史，并把输入数量作为新奖池的完整库存。此操作用于下一场活动；正在进行的活动需先核对实际剩余礼品，不能通过新建满库存重复发奖。奖签抽完后停止，不自动补签。

## 数据、备份与恢复

| 文件或目录 | 用途 |
| --- | --- |
| `data/lottery.sqlite` | 当前及历史奖池、库存、抽奖记录 |
| `data/lottery.sqlite-wal` / `data/lottery.sqlite-shm` | SQLite 运行文件，不要在运行时删除 |
| `data/backups/` | 启动、每 20 条新结果及管理操作前生成的数据库备份 |
| `data/service.log` | 后台运行日志 |

运行数据全部由 Git 忽略，不上传远程仓库。Git 只保存代码；换电脑时需另行备份和转移抽奖数据库。

使用管理区“备份数据库”获得完整 SQLite 文件。服务运行时不能只复制主数据库文件，因为新记录可能还在 WAL 文件中。恢复命令：

```powershell
.\scripts\Restore-Backup.ps1 -Backup 'D:\备份目录\lottery-backup.sqlite'
```

脚本先验证备份、停止后台服务，再将恢复前的数据库文件保留到 `data/before-restore-时间/`，恢复并重新启动。若使用前台服务，先在原终端 Ctrl+C 停止。恢复后进度回到备份时刻，需核对备份之后已发礼品；不要删除 `data/` 来修复或重置奖池。

## 更新代码与回退

更新已有仓库时，在目录中运行：

```powershell
node scripts/service.cjs stop
git pull --ff-only
node scripts/service.cjs start
```

若有未提交的本地修改，先提交或备份，再拉取。页面文件修改后刷新浏览器；后端文件修改后重启服务。更新代码不会删除 `data/` 中的库存和记录。

本地抽奖服务提交为 `dc2ea04`，整合前代码为 `12e22d6`。代码回退使用 `git revert dc2ea04`，回退会恢复原浏览器抽奖方式，因此应先停止服务并备份数据。后续修改可能造成回退冲突，需按 Git 提示处理后再提交。Git 回退不恢复 SQLite 抽奖进度；数据恢复使用上面的备份方案。

完整概率表、开源方案调研、接口和迁移细节见 [本地抽奖服务说明](docs/LOTTERY_SERVICE.md)。
